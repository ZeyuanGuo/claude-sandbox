# 网络设计

目标容器按普通服务器方式使用网络：程序不设置代理变量，系统照常解析域名并连接目标地址。外层网络只允许受控 DNS 和策略声明的 TCP 端口；HTTP/HTTPS 会被透明网关解密，其他协议没有直通路径。

## 两条公网路径

DNS 路径：

```text
目标程序 -> 只读挂载的 /etc/resolv.conf -> 受控 DNS 172.28.0.4
         -> 父代理 11450 CONNECT 到固定 1.1.1.1:443
         -> TLS SNI cloudflare-dns.com -> DoH wire format
         -> 校验公网地址 -> 记录 DNS 租约 -> 返回目标程序
```

Web 路径：

```text
目标程序 -> 普通目标 IP:80/443
         -> 目标网络 nftables -> 透明 mitmproxy
         -> 核对 Host/SNI、原始目的 IP 和 DNS 租约
         -> strict 请求审核或 daily 直接放行；旁路记录请求
         -> 父代理 11450 CONNECT 到已解析的目标 IP
         -> 公网
```

## SSH 路径

SSH 不进入策略网关，也不使用 HTTP 父代理。启用 `host.yaml` 的 `ssh.enabled` 后，控制器只把 `ssh.allowed_addresses` 中的精确 Tailscale IPv4 地址和 `ssh.ports` 中的端口写入目标、网关和宿主门禁；当前主机使用 `tailscale0`、端口 `22` 和 `10090`。网关通过宿主上游网桥为这些地址建立 `/32` 路由，宿主在转发到 Tailscale 前做源地址伪装。未登记地址、未登记端口和非 Tailscale 地址仍由默认拒绝规则阻断。

宿主 `~/.ssh/config` 及其 `Include` 的 `~/.local/share/gamma-ssh` 目录以只读方式同路径挂入目标；后者包含本机 SSH 配置使用的密钥和 `known_hosts`。挂载不会复制凭据，也不会使目标获得 Docker、宿主网络命名空间或策略文件的权限。配置更新只在下一次停止后 `init` 重新生成 Compose 时进入容器；运行中的容器不会被热修改。

SSH 连接不经过 mitmproxy，因此没有 SSH 明文审计。仍会有目标 cgroup 的 `connect()` 记录和目标/网关 PCAP；凭据泄露风险与其他已挂载宿主凭据相同。主机迁移或 Tailscale 地址变化后，必须更新精确地址列表并重新执行正向 SSH 与未登记目标负向验证。

宿主配置默认填写 `127.0.0.1:11450`，并用 `upstream.expected_exit_cidr` 声明允许的公网出口范围。DNS 和网关实际从内部上游网桥连接该网桥的宿主地址；目标容器看不到这个地址。父代理不决定放行规则，但必须把所有连接强制送到指定出口，不能回退到其他节点或直连。每台服务器以自己的主机配置和启动探测为准，真实出口和凭据不进入仓库。

## 组件职责

| 组件 | 只负责什么 |
|---|---|
| 目标 nftables | 只允许受控 DNS 和策略用到的 TCP 端口；把 Web TCP 透明送到网关 |
| 受控 DNS | 按策略接受域名，经父代理发出 DoH，拒绝私网/保留地址并签发短期名称-IP租约 |
| mitmproxy addon | 解密 HTTP/HTTPS，核对原始目的地址、DNS 租约和 Host/SNI；记录请求并立即流式转发响应 |
| 宿主父代理门禁 | 运行时只允许回环和本项目 DNS/网关访问 `11450`，并按配置允许目标访问精确 Tailscale SSH 地址/端口；停止和重启恢复时只允许回环；拒绝外部/LAN 和其他网桥 |
| 宿主 `11450` | 把 DNS 和已批准 Web 连接强制送到指定出口；出口失败时直接失败，不参与项目策略 |
| tcpdump 与 cgroup eBPF | 保存目标、DNS、网关实际数据包，以及目标 cgroup 的执行、连接和常规 UDP 发送调用 |
| network watchdog | 检查上述进程身份，并续期三处网络命名空间中的短期放行项 |

目标不加入 `upstream_net`，不能直接访问宿主代理。`upstream_net` 从创建起就是 Docker 内部网络，没有普通公网路由；容器启动前，宿主 nftables 已只允许 DNS 和网关连接 `upstream.cdm.test:11450`，另按 SSH 配置建立精确 Tailscale 转发。宿主本机进程仍可通过回环使用父代理。目标没有 `NET_ADMIN`，不能修改路由或 nftables；宿主 Docker socket、策略、审计目录和网关私钥也不挂入目标。

## DNS 约束

严格和日常模式都解析普通公网域名并记录结果；DNS 不作为域名白名单。严格模式在后续 Web 请求解密后暂停审核，日常模式按默认 Web 规则处理。DNS 成功只表示名称得到公开地址，不表示 Web 请求一定获准。两种模式都遵守下面规则：

- 不使用宿主默认 DNS，也不让目标直接访问外部 53/853。
- DNS 日志用于发现解析过的名称和异常结果；普通公网域名不需要先加入 Web 策略才能解析。
- DoH 连接使用固定公网 IP，TLS 仍校验 `cloudflare-dns.com`，因此本机不需要先解析 DoH 服务名。
- 双跳链路的首次 TLS 握手失败时，只在同一父代理、同一 DoH 地址上重试一次；不切换解析器、出口或直连。
- DoH 短暂失败时，只能复用本进程刚验证过的同名、同查询类型响应；缓存最晚在原 TTL 与 60 秒宽限结束时失效。回退答案统一返回 `TTL=0`，内部租约不晚于原缓存的绝对到期时间，并记录回退原因和到期时间。缓存到期后返回失败，不改用宿主 DNS、其他解析器或直连。
- 只接受 A、AAAA、SVCB 和 HTTPS 四种普通单问题查询，以及 glibc 使用的空 EDNS0 OPT；其他查询类型和 EDNS 选项载荷在本地失败，不发往 DoH。
- 校验响应码、问题、记录所有者、CNAME 链和 A、AAAA、HTTPS/SVCB 地址提示；附加区不能给业务地址签租约。私网、回环、链路本地、保留、组播和元数据地址一律返回失败。
- 每次成功解析先同步保存审计记录，再签发 `(域名, IP, TTL, 租约编号)`。TTL 取完整 CNAME 链和终端地址记录中的最小值；实时 DoH 新响应自身的 TTL 为 0 时只返回 DNS 答案、不签出站租约。为兼容应用略长于 DNS TTL 的本地缓存，同一域名和同一已验证公网 IP 在 TTL 后还有 60 秒连接宽限；未解析过的新 IP 没有宽限。现有客户端连接复用同一目标时也不因 TTL 到期抖动；切换 IP、端口或主机名仍重新核验。
- `canary.test` 是封闭门禁的本地静态记录，不发往公网。

目标不使用 Docker 内置的 `127.0.0.11` 转发，避免 Docker 内置解析器在短 TTL 或双栈查询时把上游瞬时失败转换成 `SERVFAIL`。只读挂载的解析文件由每次 generation 根据固定目标网段生成；DNS 原始请求和响应保存在 `runtime/dns/queries.jsonl`，实际数据包保存在运行编号下的 `dns.pcap*` 循环文件中。

## Web 策略

| 策略 | 未命中具体规则的公网 Web 请求 | 用途 |
|---|---|---|
| `strict` | 解密后暂停，等待一次性审核 | 新软件、新认证方式和异常流量发现 |
| `daily` | 普通公网域名的 HTTP/80、HTTPS/443 直接放行并记录 | 已完成初步分析后的日常开发 |

两种策略都先执行明确规则：

- 直接 IP 默认阻断；用途明确的精确 IP、端口和路径可以单独登记。
- 特殊主机名、已登记公共 DoH、异常端口和不能解密的 TLS 阻断。
- HTTPS 必须满足请求域名、客户端 SNI 和 DNS 租约一致。
- mitmproxy 关闭 `rawtcp`；原始 TCP、请求 Upgrade、TLS 内应用层 `CONNECT` 和上游 `101 Switching Protocols` 不转发。
- 策略摘要或请求处理异常时在本地失败，不改成密文直通或宿主直连。审核存储由网关健康检查定期实写检测；发现故障后，后续请求在本地失败。
- 严格模式中，具体允许规则只有设置 `allow_sensitive_headers: true` 才会自动匹配带认证头、Cookie 或 API key 的请求；否则请求进入审核。

日常模式允许普通公网网站按正常方式携带登录信息，这是“正常 Web 默认可用”的一部分。此时 `allow_sensitive_headers` 不是全局防泄漏开关；需要禁止的站点或路径必须写明确阻断规则，使用后仍按明文记录审查。

严格策略的一次批准只绑定当前请求哈希、策略版本和短有效期。日常策略中的允许请求不进入审核队列，也不为每个请求同步执行磁盘 `fsync`；审计盘健康由容器健康检查独立探测。故障发生到下一次健康检查之间可能仍有请求发出，发现后才阻断后续请求。严重的请求处理或审核状态错误会永久锁存，健康探针不能清除，只能通过重建网关恢复。响应不按域名、内容类型或大小分类处理：除明确禁止的协议升级外，收到响应头后统一逐块转发。flow 保存请求、响应头、状态和传输结果，不缓存响应正文。

## 审计失效时的处理

目标、DNS 和网关的允许地址或端口都存放在 5 秒超时的 nftables set 中。watchdog 每秒检查：

- 目标、DNS、网关仍匹配启动时记录的 PID、启动时间和可执行文件路径/设备号/inode；
- 目标 PCAP、DNS PCAP、网关 PCAP 和目标 cgroup eBPF 都仍存活、未暂停，且上述完整进程身份没有变化。

检查通过才原子续期。watchdog 或任一探针退出后不再续期，集合自动清空，目标 DNS/Web 和 DNS/网关到父代理的连接都会停止。2026-07-29 的故障测试已实际终止目标 PCAP，并确认 5 秒后集合为空、HTTPS 和 DNS 均失败。

网关健康检查会实写审核目录，但这项机制仍不检查全部审计文件、磁盘剩余空间、tcpdump 内核丢包计数或 eBPF 丢事件。进程存活不等于证据一定完整；这些情况仍由存储预检、日志和使用后审查发现。

## 已证明与未证明

当前已证明：

- 容器没有代理变量或专用 CA 路径，系统 curl、Conda curl、系统 Python、已登记 Conda 环境和 Node 都能透明访问 HTTPS。
- 普通 A/AAAA 查询经父代理上的 DoH 返回；外部 DNS 被阻断。
- 新客户端连接的 IP 必须与当前租约或其 60 秒宽限期一致；已核验的客户端连接会固定绑定目标，未解析 IP、伪造地址或切换目标仍返回本地 `invalid-destination`。
- 公网和未登记目标的 TCP/22、原始 TCP、协议升级、应用层 `CONNECT`、元数据地址和策略/审核故障不会到达公网；登记的 Tailscale SSH 例外尚未在当前运行容器中应用验收。
- 必要审计探针退出后网络放行项按期过期。

当前没有证明：

- 容器等同于完整虚拟机或能隐藏全部硬件、内核和挂载信息；
- 任意 TLS 实现、证书固定、QUIC 或 HTTPS 内再次加密都能得到可读语义；
- 高并发、长连接、极大正文下没有 PCAP 丢包或 eBPF 丢事件；
- 一个已验证软件的新版本、账号模式或第三方插件会保持相同行为。

新认证方式、未知联网组件、软件升级或无法解释的目标出现时，应回到严格策略重新发现，而不是扩大当前结论。
