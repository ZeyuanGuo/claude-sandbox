# 初始放行同时约束域名、协议、端口与 TLS 身份

放行 Web 流量时，域名、受控 DNS 结果、协议、端口和 TLS SNI 必须一致。严格策略默认精确匹配域名；确认可信且必要时，才能批准整个子域范围。日常策略可默认允许新的公网 HTTP/HTTPS 域名，但不能放宽地址、端口、身份、解密和审计检查。

默认拒绝直接公网 IP、UDP/QUIC、外部 DNS、私网、链路本地和云元数据地址。SSH、特殊下载以及无法验证 SNI 的通信必须单独批准。规则只能确认通信对象，不能证明请求正文安全。

当前透明实现已经闭合这一绑定：受控 DNS 经父代理发出 DoH，校验公网响应并签发短期 `(域名, IP)` 租约；透明网关取得连接的原始目的 IP，并要求 Host、SNI、租约和实际目的地址一致。为兼容应用 DNS 缓存，同一名称和同一已验证公网 IP 在 TTL 后保留 60 秒连接宽限；新 IP 仍必须先经过受控 DNS。网关再通过父代理连接这个已确定的 IP，因此父代理不需要重新解析业务域名。发布策略默认拒绝直接 IP；私有直连端点需要部署者在本机新增精确规则并重新验收。
