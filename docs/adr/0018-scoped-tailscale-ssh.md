# ADR 0018：精确 Tailscale SSH 转发

状态：已决定，等待下一次容器初始化应用

## 背景

宿主机的 `~/.ssh/config` 通过 `Include` 使用 `~/.local/share/gamma-ssh/config`，其中的 SSH 密钥和 `known_hosts` 位于同一目录。当前运行中的目标容器只挂载了 `~/.ssh`，没有挂载这个 `Include` 目录，因此容器内的主机别名和密钥路径不能复用宿主已经验证成功的配置。用户需要容器内的 Claude Code、Codex 等程序访问宿主和 Tailscale 内网主机，同时不影响当前运行容器。

## 决定

1. `config init` 在源目录存在时，以只读同路径挂载 `~/.local/share/gamma-ssh`；`~/.ssh` 继续只读挂载。
2. `host.yaml` 的 `ssh` 段只允许显式列出的 `100.64.0.0/10` IPv4 地址、接口名和端口。当前主机登记端口 `22`、`10090`，地址列表来自宿主实际 `ssh -G` 与无副作用登录验证。
3. SSH 不进入 mitmproxy 和 HTTP 父代理。目标、网关和宿主门禁分别建立精确地址/端口规则；网关通过宿主桥建立 `/32` 路由，宿主在 Tailscale 接口上做源地址伪装。未登记地址、端口和公网 SSH 保持默认拒绝。
4. SSH 开关、接口、地址和端口写入运行清单快照。只修改主机配置不会使当前运行实例或审计恢复路径提前启用 SSH；下一次 `init` 才生成新快照和挂载。
5. SSH 的目标、端口集合使用与 DNS/Web 相同的 5 秒 watchdog 租约。SSH 只留下 cgroup `connect()`、目标/网关 PCAP 和 SSH 返回码，不生成明文 flow。

## 原因

精确地址列表能覆盖已验证的校内组网主机和宿主，同时避免把整个 Tailscale 地址空间或任意 SSH 目标交给容器。只读挂载保留宿主的主机别名、`ProxyJump`、密钥和主机密钥校验配置，且不允许目标修改这些文件。规则写入 Compose 生成和宿主门禁配置，但不在运行中热挂载；因此当前容器继续使用原来的网络和文件状态，用户可在允许中断时统一执行下一次 `init` 与启动验证。

## 限制

SSH 不是可解密的 Web 流量，平台不保存 SSH 会话正文。Tailscale 地址变化、SSH 配置变更或新增主机必须更新 `host.yaml`，重新初始化容器，并同时完成已登记目标正向测试和未登记目标负向测试。这个决定不证明已应用到当前运行容器；应用前的现场证据和应用后的验收必须分开记录。
