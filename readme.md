# 受控开发机

这是一套面向单个用户的长期开发沙箱。项目目录直接挂载，全部 GPU 可见但不独占；目标程序像普通服务器一样发起 DNS、HTTP 和 HTTPS，不设置代理变量。外层网络把这些请求送到受控 DNS 和透明解密网关，并由宿主保存 DNS、明文、连接记录和三处 PCAP。

当前第一套检测对象是 Claude Code。历史 API-key 基线已经覆盖严格发现和真实开发任务；透明网络本身已经通过门禁、运行时兼容和审计失效测试。公开策略不包含历史私有 API 端点，账号登录、新版本和新增联网组件仍要作为新的基线重新检查。仓库文档不硬编码“当前正在运行的策略”；以 `sandboxctl status`、`audit status` 和活动运行清单为准。

## 平时使用

```bash
cd "$HOME/claude-sandbox"
sudo bin/sandboxctl shell
cd "$HOME/project"                 # 或其他已挂载项目
claude
# 或
codex
```

沙箱持续运行时，日常进入不需要逐项检查。环境刚启动或切换过策略、准备长时间使用、登录或请求被阻断、增加新 MCP/插件时，再按 [用户使用指南](docs/user-guide.md) 检查状态和流量。退出 shell 不会停止沙箱。

严格策略在解密后暂停未知 Web 请求；日常策略允许普通公网 HTTP/HTTPS。两种模式都解析普通公网域名，并保存请求正文、双向头字段、响应状态和传输结果；响应正文直接流式转发，不缓存。直接 IP 默认拒绝；外部 DNS、SSH、UDP、非 Web 协议、协议升级、特殊主机名和已登记 DoH 仍由外层阻断。遇到请求被拦截、准备增加 MCP/插件，或需要切换模式时，按 [Claude Code 使用与审计手册](docs/targets/claude-code.md) 操作，不要在容器内配置代理或改 DNS。

## 框架怎么工作

```text
目标容器
  -> 普通 DNS 进入受控 DNS；受控 DNS 经 11440 查询 DoH
  -> 普通 HTTP/HTTPS 被外层透明重定向到解密网关
  -> 网关核对 DNS 租约和目标 IP，执行 strict/daily 策略并保存请求明文
  -> 内部上游网桥的宿主地址:11440 -> 父代理提供公网出口

宿主同时记录
  -> 目标进程的 exec/connect 事件
  -> 目标、DNS 和网关三处 PCAP
  -> DNS 查询、网关请求、响应元数据和审核状态
```

上游代理只提供出口，不决定放行。网络策略由网关执行，PCAP/eBPF 负责观察；目标程序不能读取或修改策略和审计记录。

宿主配置仍写 `127.0.0.1:11440`。运行时上游网桥没有直接公网路由，宿主 nftables 只允许回环和本项目 DNS/网关访问这个端口；停止时与宿主重启后则只允许回环。目标、其他网桥和外部/LAN 不能借用它。

## 当前边界

- 当前验证的是透明 DNS/HTTP/HTTPS 路径，不是完整虚拟机隔离，也不保证应用在 HTTPS 正文内再次加密时仍能看到语义。
- Claude 会发送沙箱内核、平台、项目路径、Git 状态、客户端版本、设备/会话标识以及对话和工具内容；当前未观察到实际时区、CPU/GPU、内存、MAC、代理或 CA 路径被发送。
- 任一登记抓包或 eBPF 探针退出后，watchdog 停止续期，目标、DNS 和网关的网络放行项在 5 秒内过期；磁盘余量、丢包和丢事件仍需单独检查。
- 新认证方式、新版本或新联网组件都是新的检测基线，应先切回严格策略。
- 原始明文和 PCAP 可能包含凭据、项目源码和完整对话，只能从宿主提权读取，不能提交到 Git。
